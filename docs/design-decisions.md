# 设计决策

本文记录当前产品边界和工程取舍。若将来引入账号、云端同步或新的内容来源，应先补充隐私、安全和运维设计，再更新本文件。

## 决策：先做静态、单机可用的练习工具

**背景：** 主要场景是家长或老师陪伴孩子完成短练习；项目不需要多人协作或在线课程管理。

**选择：** 保持静态托管，不引入服务端、账号或遥测。成绩和自定义题包存放在当前浏览器。

**影响：** 部署成本和数据收集面较小；数据不会自动在设备间同步，浏览器站点数据被清除后可能无法恢复，因此提供题包导出作为备份路径。不要把浏览器本地分数当作可信的成绩记录。

## 决策：Vite + 原生 JavaScript ES modules

**背景：** 两个页面共用题库和状态能力，但旧式全局脚本会让状态和依赖难以追踪。

**选择：** 使用 Vite 管理多页构建，以原生 ES modules 组织 UI、题库领域逻辑和存储适配器。

**影响：** 页面仍保持轻量，不需要大型 UI 框架；模块之间的依赖更显式。Vite 负责开发服务器和打包，不意味着应用需要长期运行的后端。

## 决策：把题目内容与交互代码分开

**背景：** 题目更新应能独立于活动界面完成；题目还需适配不同年龄段、学科和题型。

**选择：** 题目使用版本化 JSON 结构；领域模块验证题目和答案映射，活动模块只处理题目呈现与作答交互。

**影响：** 新题型仍需相应 UI 和测试，不能仅靠添加 JSON 自动获得新交互。现有样例内容未经课程审校，格式正确不代表教育内容正确。

## 决策：数据保存在用户浏览器

**背景：** 为当前单人陪伴场景避免账户和集中保存儿童练习记录。

**选择：** 使用浏览器本地存储保存分数、挑战纪录和自定义题包；通过用户主动操作导入或导出 JSON。

**影响：** 数据限定在浏览器与站点来源内，刷新后可复用；换浏览器或清理站点数据会丢失本地状态。存储容量有限，不适合大量媒体或长期学习档案。

## 决策：用 Node 内置测试工具覆盖纯逻辑

**背景：** 题库筛选和格式校验不需要真实浏览器，可以在轻量环境中重复检查。

**选择：** 使用 Node.js `node:test` 测试领域规则和存储边界，并对确定性领域模块生成覆盖率报告；另由 lint、格式检查和生产构建发现静态问题。

**影响：** 覆盖率报告范围不包括完整 UI；自动化测试不能覆盖浏览器排版、配对交互、触屏或屏幕阅读器行为，这些场景需要浏览器手动验证。覆盖率数值以实际报告为准，不预先承诺指标。

## 决策：Pages 项目站点显式设置资源基础路径

**背景：** GitHub Pages 项目站点通常位于 `/<repository>/`，构建资源若使用根路径可能加载失败。

**选择：** Vite 构建读取 `VITE_BASE_PATH`。Pages 工作流从仓库名生成路径；Release ZIP 使用相对路径构建。

**影响：** 发布设置与仓库名相关；改仓库名或切换自定义域名时，应重新检查基础路径和构建产物。

## 内容审校与范围

目前随项目提供的 64 道题只用于展示数据形状和活动流程。项目不宣称符合特定课程标准、年龄评估或专家审校。涉及课程真实性、答案争议或儿童隐私的改动，应由成年人检查后再合入。账号体系、云同步、排行榜和行为分析不在当前范围内。
